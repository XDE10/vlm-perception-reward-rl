# 批准子集训练入口与 A100 验收

本版承接 2026-10-24 用户委托 DeepSeek 逐题审核的 release。批准对象以 `data/delegated_ai_releases_20261024/manifest.json` 为准，不扩大到原始全量池。所有命令从 `D:/Users/Mr.Z/Desktop/modern_genai` 执行。配置中的绝对路径在迁移到 Colab/Linux 时必须整体改为实际根目录；数据、图片与 manifest 哈希保持一致。

## 当前实现与边界

- 项目一：真实 HF Trainer 完整回答监督 SFT；真实 TRL GRPO / Dr.GRPO 训练入口，答案奖励由独立进程 Math-Verify 保守判分。raw 与 compact 使用同题批准交集，原生题和精炼题不混入对方 arm。默认配置只跑 2 步 A100 smoke，不是最终实验步数。
- 项目二：真实单 GPU 学生 rollout、双教师按域分时加载、相同学生前缀与 token 序列的 reverse KL、共同有效词表重归一化、梯度累积、优化器/调度器/RNG/数据位置断点。只有一个教师同时驻留。域轮换保持数学/代码等权，不宣称批准后的题型配额仍为原 1250/1250。
- 项目三：真实 VLM 感知监督 SFT 入口；固定 ID 的原图/黑图/无图/中央遮挡诊断入口。GRPO 代码路径只支持显式 `reward_mode=answer_only_baseline` 的答案奖励基线。**完整感知类别覆盖与视觉事实奖励尚未成立，因此没有放行核心感知 GRPO，也没有虚构完整推理 CoT。**

未加载 7B/VLM 权重，未运行 CUDA，没有 A100 显存、吞吐或准确率实测。CPU 小模型测试覆盖真实 HF SFT 优化/恢复、真实 TRL 两种策略目标的单步、OPD 参数更新与教师冻结；不替代真实 VL processor 的图像 token 展开、A100 rollout 和优化器恢复验收。

## 项目一：先 SFT，再从合并 SFT 基座运行 RL

配置目录：`project_blueprints/configs/approved_release_20261024/`。

```powershell
python -m scripts.train_project1_sft --config project_blueprints/configs/approved_release_20261024/project1_raw_sft_smoke.json
python -m scripts.train_project1_sft --config project_blueprints/configs/approved_release_20261024/project1_compact_sft_smoke.json
python -m scripts.train_project1_rl --config project_blueprints/configs/approved_release_20261024/project1_compact_grpo_smoke.json
python -m scripts.train_project1_rl --config project_blueprints/configs/approved_release_20261024/project1_compact_dr_grpo_smoke.json
```

SFT 默认额外导出 merged 权重及 `weight_manifest.json`。RL 从此本地合并基座加载并新增 LoRA；beta=.04 时禁用新 RL adapter 得到固定 SFT reference。**禁止直接把训练过的 SFT adapter 当作 RL adapter 再 disable，否则 reference 会退回初始模型。** 该入口已强制检查合并身份与文件哈希。

GRPO 使用组内标准化；Dr.GRPO 使用固定最大完成长度归一化、`scale_rewards=none`。completion 上限 2048，组大小 4，截断样本屏蔽策略显式配置。实际有效组与梯度必须上卡观察。当前 RL smoke 只复用批准的同题训练子集作工程检查；最终 RL 独立题池、训练步数与完整实验矩阵另行封存。

## 项目二：双教师分时 OPD

```powershell
python -m scripts.train_project2_opd --config project_blueprints/configs/approved_release_20261024/project2_opd_smoke.json
```

实际 tokenizer 映射来自固定 revision 审计，生成与教师都使用学生 token IDs，不做解码后再分词。温度为 1；抽样限于共同支持词表。数学/代码各一个域 block 的 smoke 会验证两个教师切换。全词表 teacher/student logits 的内存开销仍需 A100 验证，未实测的单卡 OOM 风险不可视为已消除。

checkpoint 保存 LoRA、AdamW、scheduler、Python/Torch/CUDA RNG 与每域读取位置，校验文件哈希。恢复时在原配置添加 `resume_from_checkpoint`，指向完整 checkpoint 目录；除此之外配置必须保持相同。已有 checkpoint 的目录禁止无意重新起跑。

## 项目三：感知监督与视觉敏感度

```powershell
python -m scripts.train_project3 --config project_blueprints/configs/approved_release_20261024/project3_perception_sft_smoke.json
python -m scripts.diagnose_project3_vision --data data/project3_all_split_candidates_v2/validation.jsonl --output runs/vision_validation_diagnostic.jsonl
```

诊断使用固定 validation ID，不向模型发送源逻辑标注/标准答案。`none` 真正移除 image 及对应视觉占位，而不是保留空图 token；遮挡为固定中央半宽半高矩形，属于输入扰动，不能当作几何真值测试。需要完整答案推理的模型必须另加载对应 adapter；当前感知原型 SFT 本身不等于数学问答能力提升。

## 数学评测、断点与验收

`scripts.evaluate_approved_math --help` 提供固定 greedy 数学评测。显式传入封存测试 JSONL、字段名、固定模型 revision、adapter 和统一 `--max-new-tokens`；输出逐题文本、token 数、触预算且无 EOS 状态、保守答案核验及 unsupported/error 统计。关系式/集合等自动判分不支持项单列，不能混称为推理错误。

HF checkpoint 保存 optimizer/scheduler/RNG 与 run identity；修改样本、软件版本或模型身份需新 output。A100 验收依次检查：2 步无非有限值、只有 assistant/response 获得监督、教师梯度为空、组奖励非全同值、图片 processor 无错位、实际峰值显存、保存后同配置恢复多一步。随后才扩展步数和完整评测。代码 dev 的构造型多解任务仍需语义 checker，不能直接以固定 stdout equality 评价所有学生输出。
