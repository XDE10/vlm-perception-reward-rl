# 共用规范：强模型合成数据、离线蒸馏与独立验证

> 2026-10-24阶段约束：用户亲自确认数据后再封板，当前暂缓GPU训练入口及批量API生产。新增[九类90样本人工审核包](<../reports/data_human_review_pack.md>)，抽样签字不等于全量质量保证。v3真30题pilot未通过门槛，不事后放宽窗口改称独立通过。发现Math-Verify对不同关系表达式的假阳性，补充类型门槛将关系式和多不同boxed转任务相关人工待审（不等同数学错误）；原始冻结结果保留。AI审核、确定性候选、人类批准三个层级分开，所有训练批准仍false。

版本：2026-10-23（精炼解答核心模块与真实API pilot更新）。状态：两轮小规模API pilot已执行；尚未批准批量训练数据，也没有GPU收益结果。适用于三个项目；不替代各项目的原始基线。

## 1. 为什么加入这项工作

公开数据可以用于研究与求职项目，没有“使用公开数据必然被淘汰”的通用规则。新增价值来自明确的错误分析、合成策略、质量验证、预算控制与受控收益；仅调用一次 API 改写公开题目不能自动成为独创数据集。

本项目表述为“基于公开种子构建经过验证的派生训练数据”，保存来源和衍生关系。公开基准继续作为独立最终评测；不为了显得原创而隐藏原始来源。

## 2. 三种不同的教师使用方式

- 离线序列级蒸馏：教师生成公开可见的解答/代码，保存后用于 SFT。
- 合成标注与数据增广：教师分类、提取、生成变式或测试。标注辅助是数据工程，不是每一步都等于模型蒸馏。
- Token 级 OPD：教师评分当前学生生成的前缀，再优化学生分布。教师可本地或远程部署，并非理论上必须与学生共卡；但接口必须支持所需前缀评分和词表信息。

普通文本生成 API、少量 top-logprobs 不自动支持任意学生前缀的完整词表 KL。项目二保留可访问 logits 的开源教师；GLM/DeepSeek API 默认用于离线解答、标注和辅助验证，不宣称直接替代完整词表 OPD。OPD 也不保证消除全部分布偏移。

## 3. API 教师如何选择

GLM 与 DeepSeek 均可作为候选，执行时根据实际开放的具体模型 ID 比较，而不是按品牌预设优劣。先用 30～50 个训练侧样本做小试，记录结构合法率、独立验证通过率、长度、延迟、费用与失败率，再选一个主生成模型。

记录 provider、model ID/版本、请求日期、提示词版本、采样参数、输出上限和服务返回元数据。别名可能漂移，无法精确固定时如实注明。结构化输出、批处理、缓存、logprobs 和 reasoning 内容是否可取得，需要逐接口核实；只使用服务正常返回的内容。

生成和验证分角色隔离：验证器不默认接收生成者的结论或评分理由。可用另一模型帮助发现争议，但多模型一致不等于真实正确，不能取代可执行判据和人工核查。核查源数据许可、输出使用条件和再分发要求后，确定数据发布范围。

## 4. 共享流水线与可追溯字段

2026-10-23 数据筛选执行约定：项目一、二复用同一封存数学 dev（256 题）及候选池文件哈希，不为某一项目重新随机划分；当前 dev 的任何具体题面、错题、换数题、改写题都禁止进入训练候选与 API 生成请求。筛选器可以只读评测内容排除重叠，但不得将命中题传给生成器“改写避重”。API 同题对照以两组共同接受题集合为准，不硬凑 1500 条；学生 tokenizer 计数、接口类型、真实通过数量与未完成验收项须写入 manifest。

先划分并封存 dev/test → 从 train 建立种子 → 自动生成候选 → schema/长度/重复检查 → 独立验证 → 人工分层审计 → 接受/隔离/拒绝 → 封存数据版本 → 受控训练。

每条记录至少保存：`sample_id`、`parent_id`、`family_id`、`source_revision`、`split`、`generation_mode`、`teacher_model`、`prompt_hash`、`request_id`、`raw_output`、`normalized_output`、`verification_evidence`、`accept_reason`、`token_usage`、`latency`、`cost`。不保存 API 密钥。

同一原题的改写、换数字和逆向题归入同一 family；划分发生在增广之前，所有后代继承父题的 split。拒绝从 test 错题派生训练数据。dev 可以用于选择方法，但一旦用于指导生成，就不能再称其独立最终验证。

本版训练增广的种子仅限 train（包括从 train 内划出的诊断池），不直接使用当前 dev 题面或其改写。若未来明确将旧 dev 转为训练种子，需要登记新数据版本、将其全部后代归入 train，并另封存未接触的新 dev；旧 dev 成绩只能作开发记录。

请求缓存键包含源 ID、提示版本、模型 ID 和采样配置；使用断点续跑、限速、有限重试、失败队列和最大费用/请求数停止条件。不因网络失败整批重跑付费请求。

### 4.1 硬性准则：盲生成＋事后验证

项目一、三合成推理训练样本时，生成请求只允许包含题目、任务格式，以及项目三经核验的初始条件；禁止包含标准答案、参考解答、由答案派生的提示或前次判分器透露的正确值。隔离请求构造器与标准答案存储，用字段白名单构造输入，检查 system/user 消息、示例、检索内容和修复消息，不能直接把整条数据记录发给 API。原题条件中的正常数值不是泄漏，不能靠“删除答案数字”实现隔离。

项目一2026-10-23更新：同题OpenR1原生/DeepSeek独立精炼解答列为核心数据研究；API难度打标失败已归档，后续不默认调用estimated_level。取消逐题LLM过程裁判请求，但不取消过程质量审核：确定性结构/噪声/答案检查只是必要条件，AI分层抽查、人工审核及可计算步骤核验分别记录，未人工审核不得标为人工金标。严格格式与透明包装规范化分别统计；规范化不新增数学推导或标准答案，保留原始文本/操作日志，冲突或缺图仍隔离。长度窗口150～1500是实验准入，不是过程正确证明。新40题pilot及事后格式复审见[执行报告](<../reports/compact_distillation_v2_20261023/执行报告.md>)；未通过冻结验收，不扩产。

教师独立生成后，验证进程读取标准答案并进行等价/数值匹配，再检查条件引用、完整性与可验证步骤。答案通过只是必要条件，不能保证过程正确。本版不允许 answer-conditioned 修复进入推理训练集；若为人工诊断保留，写入单独隔离目录，不作为训练候选。

每题生成次数设显式上限 `max_generation_attempts=3`（首次加最多两次重采样，具体预算可预先修改）。错误结果重新盲采样，不向生成器反馈标准答案或参考过程；达到上限仍不合格则丢弃/隔离，记录原因。传输重试与内容重采样分开计数，同时受总请求数、费用上限约束。对新变式题须先建立独立可验证答案，不能把生成者自己给出的答案当独立标准。

## 5. 质量层级和人工审计

候选不等于银标，银标不等于金标：自动验证通过可称银标；人工查看原题/图像并核实判据的部分称人工核验集。用于改提示词的样本是开发集，不再作为独立审计集。

审计在提示/规则冻结后执行，随机与分层抽样结合，覆盖被接受和被拒绝样本。报告题目级与事实级合格率、抽样方法、错误类别、接受率和覆盖率；不只报告筛完之后的高准确率。多条事实属于同一题时统计存在相关性，置信区间应按题目聚类或直接用题目级指标。

例如随机审核 100 题有 96 题合格，只能报告 96/100；二项 Wilson 95% 区间约 90.2%～98.4%，不能宣称总体必然超过 95%。这是假设性计算示例，不是本项目结果。独立性或随机抽样不满足时还需说明偏差。

原始人工符号标签也可能缺失或出错。最终答案匹配不证明每个推理步骤成立；参考代码通过合成测试也不证明测试充分。保留人工发现的反例，这是方法局限的证据。

## 6. 费用与工作量

先测小批的实际输入/输出 token、重试率、接受率与耗时，再估算全量。成本包含失败、重试、验证模型和人工复核；计费单价在调用当天按实际模型记录，不使用“几块钱/半小时/准确率 99%”保证。

预算优先顺序：项目三感知语义过滤；项目一同题解答蒸馏；必要时少量代码测试补全。先追求数百条有效样本的可解释实验，不默认扩到几万条。

## 7. 面试与验收材料

展示原始种子、一次失败生成、验证器如何拒绝、最终接受样本，以及相同预算下训练效果变化。能够回答“为什么没有直接用公开解答”“收益来自题目还是解答”“教师是否看到答案”“测试是否被用于生成”。

可用表述：“基于公开种子构建符号引导/验证驱动的合成数据管线，保存生成与筛选轨迹，并通过配对实验评估收益。”条数、合格率、成本与涨点只填真实测量值。
