# 项目三：多模态几何推理的视觉依赖性与感知奖励研究

> 2026-10-24数据阶段：从2096条唯一关联train中按固定哈希取200题，已生成有限AST/关系分类原型、真实原图和[30条双定位关联核查单](<../reports/project3_perception_review/manual_link_review_30.md>)。1922条diagram原文中454条支持，分类为450条visual_candidate、4条text_explicit、1468条uncertain（含不支持/空源项）；162/200题有视觉候选，81%不是图像独占事实准确率。44条视觉候选坐标越界已留证。有限text蕴含规则本样本命中0，不能把未匹配文字直接当视觉金标。固定Angle→Length→Parallel→Perpendicular→Tangent排序、去重及冲突隔离的200题[规范预览](<../reports/project3_perception_review/canonical_preview_说明与200题预览.md>)已落盘，生产奖励parser未改。所有human_review=pending、training_approved=false，Congruent及符号值仍保守uncertain。当前只做数据审核，不写训练脚本。

版本：2026-10-23（真实标注关联与MathVista重叠审计更新）。性质：数据关联已推进，视觉独占事实审核与训练待实施。目标是验证视觉证据与奖励有效性，不预先承诺 RL 优于 SFT 或奖励彻底防作弊。

## 1. 项目目标

研究 Qwen2.5-VL 在几何题中是否使用了必要的图像信息，以及对结构化视觉事实进行奖励能否减少感知错误。先诊断、再构建监督、最后训练与验证。

区分三个层次：答案是否正确；感知事实是否正确；改变关键图像信息后模型是否作出合理变化。只看最终答案或输出 `<perception>` 标签，不能证明视觉理解。

最终交付：原始标注与训练数据关联表、视觉必需子集定义、感知验证器、五个模型状态、正常/无图/遮挡诊断、Geometry3K 与 MathVista 结果及错误案例。

## 2. 模型、框架和硬件

- 模型：`Qwen/Qwen2.5-VL-3B-Instruct`，记录模型、processor、tokenizer 与图像预处理 revision。
- RL 框架：`hiyouga/EasyR1`，锁定 commit 与依赖；不默认最新示例完全适配该模型。
- 首选单 A100 80GB；40GB LoRA 路径先做完整 rollout/更新验收。
- 初始只训练语言部分 LoRA，rank 16，视觉编码器与投影层的冻结策略显式记录。若框架不支持该精确组合，先完成适配并验证，不静默换成全参数训练。
- 图像分辨率/像素预算、prompt 长度、回答长度和 group size 都影响显存。图像过度压缩可能使角度标记看不清，应同时检查可读性。
- 不把“EasyR1＋Unsloth”当作可直接组合的配置项；只有版本兼容和真实测试后才使用。

官方 EasyR1 显存表是估计值，不能作为本项目硬件验收结果。

## 3. 数据集与划分

### 3.1 主数据 Geometry3K

使用 `hiyouga/geometry3k`，目标沿用原始划分：train 2101、validation 300、test 601。执行时核对实际 split 名、行数、原始 ID 与哈希；不通过挪用验证/测试题补齐数量。

该包装数据提供 images、problem、answer，不能假设直接有 `diagram_logic_form`。需要从原始 InterGPS 数据取得人工标注，再按原始 ID、图像哈希和题目核验关联。不要用行号猜对应关系。

### 3.2 结构化感知标注

采用“官方标注自动解析 → 规则过滤 → 人工抽检”的路线，不从零手工标注全部题目。InterGPS 官方解压脚本包含 `logic_forms.zip`，先枚举其中真实文件名、ID 与标注类型，区分人工标注与解析器预测；本轮未下载压缩包逐题验证，因此不宣称全部 3002 题都有完整可靠的同名 JSON 字段。

先对 train 2101 题批量生成候选：关联 diagram/text logic forms，解析成 AST，规范化实体、对称关系和单位，再排除题干显式条件。文本可推导关系需要保守规则或人工复核，不能只做字符串集合差。每条候选保存原始表达式、规范化表达式、筛除理由、规则版本与来源 ID。

从训练候选中分层抽检 100～200 道，覆盖关系类型、难度、OCR、疑似歧义及过滤失败案例。这是检查/修订已有候选，不是从头写全套标注。将一部分抽检题用于规则开发，另封存一部分审计题检验规则精度；修改规则后不能把开发题上的一致率当独立准确率。

为每条事实记录：实体、关系、数值/单位、图像区域或符号、是否在题干显式出现、是否仅由题干可推出、是否有歧义。只有可信的图像独占事实进入首版感知奖励。

题干和图形标注的排除需要语义判断，不是字符串相减。图中画得像垂直但无符号/题设保证时，不能自动标成垂直。

自动候选争取覆盖完整训练划分，但逐项报告关联成功数、解析成功数、有视觉独占候选数、可信可训练数与人工审计精度。不能把“2101 道候选”写成“2101 道已核验标签”。无需将正式训练限制在人工抽检的 100～200 题上：通过规则与抽检准入的较大候选集可以用于训练，低可信样本隔离或屏蔽感知项。

核心 V1～V4 使用相同有效训练题集，额外视觉监督是否使用由组别决定。规则定稿前预设审计准入标准，例如关键关系抽检 precision 目标至少 95%，同时报告样本量与不确定性；达不到时收缩关系类别或修订规则，不靠多训练掩盖噪声。若最终只剩约 150 题，定位为奖励原型并限制更新，不能直接视作已具备完整泛化实验的数据规模。

### 3.2.1 符号引导的强模型语义过滤

在自动 AST 解析/规范化之后，将 train 题干、text logic forms 和 diagram 候选事实发给选定 GLM/DeepSeek 文本模型做语义分类。不给最终答案；让模型给每个已有候选 ID 标注 `text_explicit`、`text_entailed`、`visual_candidate` 或 `uncertain`，返回对应题干片段与简短依据。只允许分类输入中已有的事实，禁止补造新关系。

`text_entailed` 表示从题干可推出；`visual_candidate` 只是“尚未在文字中找到依据”，不能证明图像确实支持它。符号源标注也可能错误、不完整，必须保留看原图核验的抽样步骤。无法确定文本蕴含时归 uncertain，隔离而非强行保留。多模型分歧进入复核队列，一致也不自动升级为金标。

先在 30～50 道训练开发样本比较规则过滤与 API 辅助过滤，再封存提示并使用独立审计样本估计误保留率/误删除率。API 文本推理替代的是部分语义审核，不是原图证据。来源、费用、金标定义见 [共用规范](<共用规范_强模型合成数据与验证.md>)。不预填“99% 准确”“2101 条全部合格”或固定处理时间。

### 3.3 MathVista 外部评测

`AI4Math/MathVista` 的 testmini 为 1000 题，保留用于最终外部评测。它包含 Geometry3K 来源，不能整体称为完全独立 OOD。

必须同时保存：

- 完整官方 testmini 成绩，附训练重叠审计结果。
- 排除 Geometry3K 来源并对题目/图像去重后的跨来源子集成绩，单独命名、公布 ID 与实际数量。

如果完整集存在训练重叠，明确标注其污染，主要泛化结论依据无已知重叠子集；不把删减子集分数当成官方完整 MathVista 分数。

## 4. 视觉敏感度诊断怎样做

先在 validation 开发诊断方法，最终测试前固定所有规则。

1. Normal：原始图像。
2. No-image：移除图像，保证 processor 和模板确实支持该输入，不留下失配占位符。
3. Black-image：同尺寸黑图，单独记录分布偏移影响，不与 no-image 合并。
4. Occlusion：遮挡已标注关键区域，控制遮挡面积并保留无关区域对照。
5. 可选反事实：人工修改单个关键数值并重新核算答案；不能任意旋转/裁剪后假定题意不变。

人工视觉必需子集：仅凭题干无法唯一确定答案、需要至少一项图中信息。标注依据来自题目本身，尽可能在查看模型输出前完成；边界案例单独标注。

模型行为分组：正常图正确/无图错误、两者都正确、两者都错误、正常图错误/无图正确。它们不是题目客观视觉必要性的替代定义。

最终报告完整 test 与人工视觉必需子集；不要用“基座刚好失败的题”事后构造有利测试集。

## 5. 输出格式与感知奖励

所有核心组统一输出结构，例如 `<perception>结构化事实</perception><reasoning>解题说明</reasoning><answer>最终答案</answer>`。标签本身不表示模型内部推理可信，外显说明只作为可检查输出。

结构化事实采用有限关系集合和实体名，例如 `Perpendicular(AB,CD)`、`Angle(A,B,C)=60deg`，具体 schema 在标注原型完成后冻结。处理实体顺序、对称关系、单位与数学等价，不用任意关键词包含判断正确。

### 5.1 感知事实的固定序列化顺序

SFT target 中的 `<perception>` 使用确定性序列化，由脚本完成，不依赖 API 输出顺序：AST 解析 → 按关系语义规范化实体/数值/单位 → 合并等价重复事实 → 检查冲突 → 固定排序 → 固定空格/分隔符输出。关系顺序显式设为 `Angle → Length → Parallel → Perpendicular → Tangent`；其他受支持关系在 schema 中登记固定优先级，未知关系隔离，不随运行自动改变顺序。

同类按规范化实体元组排序，再按规范化值和单位排序；完整标签按固定字典序处理，例如明确 `A10` 与 `A2` 的排序，不依赖本地语言环境。无向线段可将 BA 规范化为 AB；Parallel/Perpendicular 的两条线可在关系定义允许时排序。角 `Angle(A,B,C)` 的顶点 B 不能被字母排序移走，只有声明为普通无向角时才可交换两端 A/C；有向角、射线、相切关系的角色不能机械重排。相同属性的冲突数值不能通过排序消除，应隔离复核。

例如同一事实集合无论原始顺序如何，均输出 `Angle(A,B,C)=60deg; Length(A,B)=5; Perpendicular(AB,CD)`。只规范化 `<perception>`，不重排需要逻辑先后顺序的解题过程。

该规则同时用于 V2 和 V8/V9 等含感知监督的数据，记录 `canonicalization_version`。RL 事实正确性仍按集合/语义匹配，不因输出排序不同扣事实分；格式指标不强制排序，避免额外改变奖励目标。

实现验收：输入置换/等价实体写法输出一致；重复事实不重复计分；角顶点/有向角色保持；冲突可检出；规范化幂等；序列化再解析保持事实语义。固定顺序有助于减少等价表达变体，但不能承诺“收敛快一倍”；实际影响需要同数据、同预算的独立消融。

### 5.2 奖励配置

首版奖励建议：

$$R = R_{answer} + \lambda_p R_{perception} + \lambda_f R_{format}.$$

初始建议 `lambda_p=0.2`、`lambda_f=0.05`，仅为 dev 搜索起点。答案奖励权重为 1；所有组格式奖励一致，感知组只增加感知项。

感知项可以采用已完整标注关系类别上的 precision/recall/F1。对无依据的事实不能一律视为错误，因为标注可能不完整；先明确覆盖范围，再惩罚覆盖范围内的错误声明。去重输出事实，避免靠重复或罗列所有关系刷分。

对于无有效感知标注的题，感知项置零且记录 mask，而不是当作感知满分。设置奖励上限，保存各分项，检查“列事实变多但解题变差”等奖励利用行为。

## 6. SFT 数据从哪里来

包装数据没有现成的完整推理轨迹。第一版可用“经核验的结构化感知事实＋标准答案”作为 SFT target，不虚构推理过程；若引入教师生成解释，需单独验证且所有相关组使用同一版本。

新增可选离线推理蒸馏：将 train 题目＋经核验的初始求解条件交给强文本模型，严格隐藏标准答案和参考解答，让它输出可见解答与最终答案。初始条件可包含文本已给事实和可靠图形事实，不能夹入求解得到的目标值；感知输出区域只保留经审计的视觉候选，不能把求解所需的所有事实都算“视觉独占”。缺失条件时允许拒答，不要求编造推导凑答案。

生成后独立验证最终答案、引用条件和关键几何步骤，优先用符号/数值检查，辅以人工审核。本版取消反推答案的候选修复模式：执行共用规范第 4.1 节，默认每题最多生成 3 次，失败则重新盲采样，超限隔离/丢弃，不能把正确答案反馈给生成器。即使最终答案匹配也继续审核关键步骤。此类辅助解答是“符号条件下生成”的训练监督，不是教师真正从图像读取关系的证明。

不保证接受 2101 条，不把没有 reasoning 的短 SFT target 直接判为无效。新数据先作为 V8/V9 配对消融：在完全相同的接受题集合上，比较“感知＋答案 SFT”和“感知＋经过验证的解答＋答案 SFT”，两组从 V0 出发，报告实际监督 token/成本差异。不能直接拿全量 V2 与少量高质量合成题训练结果归因于推理内容。

V8/V9 最多新增两个 SFT 作业；若 V2 的题集合与所有配置完全匹配，可复用 V2，因此新增一个。V3/V4 仍从 V0 出发完成原奖励对照，不因加入合成解答而悄悄改变 RL 起点。

保存 SFT 监督字段与 RL 可用标注，使读者看清额外监督来自哪里。感知奖励组使用了更多信息，因此必须增加相同感知标注的 SFT 对照。

## 7. 实验数量：5 个核心状态，4 次训练

1. V0：原始 VL 模型，所有诊断与正常评测的基线。
2. V1：答案监督 SFT，使用同一训练题集与统一输出协议；感知区域可留空，不伪造标签。
3. V2：感知事实＋答案监督 SFT，判断额外感知标注本身的价值。
4. V3：从 V0 开始，答案＋格式奖励 GRPO。
5. V4：从 V0 开始，与 V3 同配置，额外加入感知奖励。

核心训练 4 次。V3/V4 的初始权重、题目、模板、更新预算、生成配置完全一致，主要因果对照是 V4−V3。V2 用于检验同种标注通过监督学习是否已经足够。

SFT 与 RL 优化方式和 token 使用不同，所以 V1/V2 与 V3/V4 的比较同时报告训练成本，不能声称只隔离了一个因素。

选做 V5：V4 去掉图像独占筛选；V6：V4 去掉错误事实惩罚；V7：统一从 V2 出发的两种 RL，需成对增加两个作业。先完成核心对照，再做消融。主要 V3/V4 建议 3 个种子。

## 8. 起始训练配置与停止条件

- SFT：LoRA rank 16、学习率 `1e-5`、1 epoch 起步，micro-batch 1，目标有效 batch 16。
- GRPO：学习率 `5e-6`、每题 4 个回答、temperature 0.8、top-p 0.95、最大回答 1024，先做 10～20 次更新 pilot。
- 参考策略为 V0，KL 建议起始 0.02；确保实际框架实现和配置一致。
- 100～200 更新是中程预算检查点，不是已证明收敛的正式上限。V3/V4 在同一预先登记的预算和检查点上比较，必要时共同扩展至 400、600 更新；是否扩展仅依据 dev、奖励信号、过拟合趋势与预算，不能看 test 决定。
- 图像 token 与文本 token 分别统计，总上下文不得静默丢图或截断答案。
- 若格式/感知奖励上涨而 dev 答案率持续下降，停止扩展训练并审计逐题输出。

EasyR1 的 batch、offload 和 LoRA 字段以锁定 commit 为准，本文不是可直接粘贴运行的 YAML。先用两个样本验证图像、prompt、奖励与样本 ID 对应，再扩大运行。

## 9. 评测基准与排行榜入口

- 域内主基准：Geometry3K test 601 题，报告完整集与预先定义的视觉必需子集。
- 外部主基准：MathVista testmini 1000 题与去来源重叠子集。
- 框架候选：lmms-eval 的 `mathvista_testmini` 任务，锁定 commit、模型适配与 processor；Geometry3K 可实现项目内任务。
- 官方对照入口：[MathVista 项目与结果](https://mathvista.github.io/)。本地跑 testmini 不等于提交正式排行榜；不要与采用不同 test 划分或抽取器的分数直接排名。
- MathVista 可能使用额外模型抽取答案；必须核查当前任务的 extractor、提示、版本、API 成本。若改用确定性抽取器，明确是自定义协议，不冒称完全复现官方成绩。

主推理协议：各模型使用同样图像处理、贪心单次回答与固定长度；多次随机采样作为补充敏感度分析。

指标：答案准确率、感知 precision/recall/F1、错误视觉事实率、格式/解析失败率、截断率、正常图与无图的配对差异、正确/错误回答长度、GPU 时长。

人工复核至少 50 个“答案正确但视觉事实错误”或相反的案例；报告选样规则，避免只展示成功故事。测试前冻结指标和子集，报告配对区间及训练种子差异。

## 10. 你亲手做的核心工作

1. 建立 Geometry3K 与原始逻辑标注的一一对应，并人工检查至少 30 个链接。
2. 批量解析官方逻辑标注，再抽检 100～200 道候选题，理解哪些关系来自符号、OCR、题干或推导；保存自动覆盖率与抽检质量。
3. 实现感知结构 parser、实体规范化与奖励测试，构造重复事实、乱列事实、矛盾事实等攻击样例。
4. 实现图像诊断：保存原图、处理后图与 processor 参数，检查遮挡真的覆盖目标区域。
5. 手工追踪一条样本从图像输入到 rollout、奖励分项和参数更新的路径。
6. 跑一次中断恢复，确认 processor、LoRA、奖励版本、数据 ID 和优化器一起恢复。
7. 分析 V3/V4 的逐题变化，区分 OCR 错误、关系识别错误、推理错误和评分错误。

核心学习量主要在数据关联、视觉标注、可靠奖励和评测；不是把框架示例里的模型名改一下。
