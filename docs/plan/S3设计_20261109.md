## 2. 视觉必需子集（`test_vn`）

一道题属于视觉必需子集，当且仅当：

1. 题面（包装数据的 `problem`，去掉 `<image>`）不含阿拉伯数字 0–9；
2. 对应 InterGPS 记录的图示逻辑式（`diagram_logic_forms_annot.json`）里至少有一个 `Equals(…, v)`，且 v 含数字。

规则只看题目和标注，不看任何模型输出。train 上 1427/2101（67.9%）满足。题面里的数字也可能只是角的编号
（例如 “Find m∠2”），这类题会被排除；规则有意保持简单，宁可少收。

## 3. CF-Geo（`cfgeo`）

### 3.1 候选规则

视觉必需的题，同时满足：

1. 图示逻辑式里所有含数字的值，都属于 `LengthOf` 或 `MeasureOf`；
2. 每个 `LengthOf` 的值是纯数字或单个小写字母；每个 `MeasureOf` 的值是纯数字；
3. 至少有一个纯数字的 `LengthOf`；
4. 目标（InterGPS 文本逻辑式 dissolved 版本中的 `Find(…)`）是长度：`LengthOf`、`PerimeterOf`、`RadiusOf`、`DiameterOf`，
   或某个 `LengthOf` 的值所用的字母，此时量纲次数 d=1；是面积 `AreaOf` 时 d=2；其他目标排除；
5. 标准答案能被 math_verify 解析；并且题面要么没有取整要求（不区分大小写匹配 `\b(round|nearest)\b`），要么取整要求是
   “nearest tenth / hundredth / thousandth”（保留 p = 1/2/3 位小数）且标准答案是纯小数。其他取整说法排除。

train 上 521 题（24.8%）满足 1–4，其中 520 题满足 5：312 题答案精确，208 题要求取到十分位或百分位。
按 test 和 validation 公开题的数量折算，编辑前约 220 题，编辑核验后预计 160–200 题。

取整题的标准答案不能直接乘 k：原答案 g 已经取整，真实值 v 只知道在 [g − h, g + h) 内（h = 0.5 × 10^−p）。
编辑后（长度乘 k，量纲次数 d，m = k^d）正确答案是 round(m·v, p)，可能不止一个值。例如 g = 56.6、m = 2 时，
正确答案可能是 113.1、113.2 或 113.3。所以取整题按集合判分：预测值必须等于集合
S_m = { round(m·v, p)（四舍五入）: v ∈ [g − h, g + h) } 中的某个数。m = 1 时 S_1 = {g}，与常规严格判分相同，
所以原图、k=1 和 k=2 用的是同一条规则。这就是 D4 预留的“按小数位推导的容差”的精确定义。

### 3.2 编辑与核验

对 k=1（擦掉后原样重画，作为编辑伪影的对照）和 k=2（长度数字乘 2）各做一次：

1. 用 OCR（rapidocr-onnxruntime 1.4.4，在沙箱里）找出所有文字框。每个纯数字的 `LengthOf` 值，出现几次就必须恰好对应几个框
   （框里是这个数字，允许带单位后缀，重画时保留后缀）；每个含数字的框都必须能由某个 `LengthOf` 或 `MeasureOf` 值解释。
   有无法解释的数字就排除这道题。
2. 擦除：把框（外扩 2 像素）填成框外 3 像素一圈的逐通道 RGB 中位数；如果这一圈颜色不均匀（附近有线条），排除。
3. 重画：k·v（整数保持整数；小数用能精确表示该值的最少位数）用 Pillow 自带字体，字号使数字高度与原数字的墨迹高度一致，
   颜色取原数字墨迹的中位数，以原框中心为中心。新字会盖住框外墨迹时，排除。
4. 核验：对编辑后的图再做一次 OCR。每个新数字都要在原位置被读出（与原框 IoU ≥ 0.3），角度数字不变，不出现其他数字；否则排除。
5. k=1 和 k=2 都通过，这道题才进入 `cfgeo`。

标准答案：答案精确的题，用 sympy 计算 k^d × 原答案，再用训练判分器确认新答案字符串与它等价；取整题记录 g、p、m 和集合 S_m。

提交进仓库的内容：题目列表（包装数据定位、像素哈希、InterGPS 编号）、每处编辑的矩形和补丁像素（PNG，只含我们填的底色和画的数字）、
编辑后整图的像素 SHA256、新答案。不提交原图。VM 下载固定版本的包装数据，贴上补丁，逐张核对像素 SHA256，有一张不一致就失败。

抽查：从通过的题中按种子 20261109 随机抽 30 道，我逐张看 k=1 和 k=2 两张图并记录结论。发现问题就修改流水线规则、全部重建，
再换一批 30 道重新抽查；不手工修单张图。这是 AI 看图核对，不是人工金标。

流水线只在 train 上开发（原型：OCR 56/60 找全，编辑核验 36/40 通过），规则定稿后对 validation 与 test 只运行一次。
如果通过的题少于 100 道，可以回到 train 上修改编辑规则再运行，每一版的规则和通过数都记录下来；E2 的分析方法不变。

## 4. 主终点与指标

所有评测：HF 贪心解码，最多 1024 个新 token，提示按第 6 节决定，批大小 32，按评测文件顺序组批，每个模型的批次完全相同；
写到上限仍没有答案的输出算错。每组只评最后一个 checkpoint。

| 终点 | 数据 | 指标 | 主比较 |
|---|---|---|---|
| E1 感知 | `val82` 原图 | v5 验证精度 = ΣTRUE / Σ(TRUE + FALSE)；认证召回 = ΣTP / Σ\|G+\|。都在全部题目（和种子）上合并计算，逐条判定直接取 `score_v5`（与训练奖励的计法相同：超过 24 条的输出不计 TRUE/FALSE，认证事实全部算漏） | RL-v5 vs RL-ans、RL-v5 vs RL-v4，两个指标各一次，共 4 项 |
| E2 读图 | `cfgeo` 的 k=2 图 | 答案准确率 | RL-v5 vs RL-ans、vs RL-v5-placebo、vs RL-blind，共 3 项 |
| E3 解题 | `test_vn` 原图 | 答案准确率 | RL-v5 vs RL-ans、RL-ans vs RL-blind，共 2 项 |

一起报告、但不计入主比较的指标：

- E1：每条输出的断言条数、UNKNOWN 占比、FALSE 占比、超过 24 条的比例；敏感性分析去掉 validation:165 和 validation:179（[勘误](../../reports/certified_fact_errata_20261109/README.md)）。
- E2：k=1 与原图的准确率及其差（编辑伪影）；k=2 上的“旧答案率”（输出等于原答案、不等于新答案的比例）；每组 k=2 与 k=1 之差；
  敏感性分析只用答案精确的题（不含取整题）。
- `test601`：原图、无图、换图三种条件的准确率；用 InterGPS 标注计算的 FALSE 率（与训练奖励同源，报告时注明）。
- MathVista testmini（S5，次要）。

## 5. 统计方法（D46）

- 每道题一个分数；有多个种子的组，先在每道题上对种子取平均。E1 的计数在种子之间合并。
- 95% 区间：按原图像素哈希聚类的配对 bootstrap，重抽图而不是题，1 万次，百分位区间，种子 20261109。CF-Geo 的题按原图聚类。
- p 值：聚类层面的配对置换检验。每个图簇内以 1/2 的概率交换两组的结果，1 万次，双侧，p = (1 + 极端次数) / (1 + 10000)。
- 多重比较：第 4 节的 9 项主比较一起做 Holm 校正。
- “能和对照区分”：Holm 校正后 p < 0.05，并且 95% 区间不跨 0。两个条件都要满足。
- McNemar 精确检验只作为单种子配对的补充报告。执行计划原本写的是 McNemar，但它假定题目独立、结果是 0/1；多种子平均后不是 0/1，
  同一张图又会出现在多道题里，所以主检验改用聚类置换。
- 判分：所有评测集都用训练用的判分器 `src/rewards/answer.py`（严格类型检查，没有数值容差，D4）。唯一的例外是 CF-Geo 的取整题，
  用第 3.1 节的集合规则；它在原图和 k=1 上与严格判分相同。
- 检验力（正态近似，假设 25–30% 的题两组结果不同）：E3（约 408 题）大约能区分 5 个百分点以上的差；
  E2（约 180 题）大约 8 个百分点以上；E1 取决于断言条数，预计区间半宽 5–8 个百分点。更小的真实差异多半会得到“不能区分”，这里提前写明。
- 评测代码的缺陷：如果在看过留出集输出之后发现解析或判分的缺陷，修复必须对所有模型同时生效，并记录修复前后的数字；
  不因此修改终点、比较对象或统计方法。

## 6. S3 的决策规则（只用 train）

样本：已批准 train 中按种子 20261109 随机抽的 64 题，带图。

| 决策 | 测量 | 规则 |
|---|---|---|
| 提示 | P0 = 现在的协议 v3。P1 = P0，再在用户消息末尾空一行加一句固定的话：`Respond in the format <perception>...</perception><think>...</think><answer>...</answer>.`。每题每个提示 4 个样本，温度 1.0（与训练相同），另做一次贪心 | 温度 1.0 下，P1 的格式率（`format_reward` = 1 的比例）比 P0 高至少 0.10，且答案准确率不低于 P0 减 0.02，才换成 P1；否则保持 P0。贪心结果只报告。换成 P1 时，所有组和所有评测都用 P1，协议编号随之改变 |
| 格式预热 | 选定提示在温度 1.0 下的格式率（`format_reward` = 1 的比例） | 低于 0.50 时，S4 加一次所有组共用的拒绝采样格式预热（执行计划第 8 节）：所有组从同一个预热 checkpoint 出发，只按格式和答案筛选，不按感知质量筛选。细节在 S4 运行前预注册 |
| 生成长度 | 选定提示、温度 1.0、写完 `</answer>` 的补全长度 | 第 95 百分位不超过 870 token 时保持 1024；否则改为 1536，并在 S4 试跑中重新测显存 |
| 分辨率 | 训练图与评测图的像素数（只数尺寸） | 保持 max_pixels = 802,816（最多 1024 个视觉 token），所有组和评测相同；报告评测图中会被缩小的比例 |
| 重要性采样（D41） | 3 步 vLLM GRPO（rl_v5，种子 1，冻结的运行时） | 每一步的 `sampling/importance_sampling_ratio/mean` 都在 [0.9, 1.1] 内，并且 `sampling/sampling_logp_difference/mean`（每个 token 的 log-prob 差的绝对值的平均）不超过 0.10，才通过；否则 S4 所有组改用 HF 生成 |

只测量、不做决策的项目：V0 在 `val82` 上的贪心输出（有图、无图，以及一个只要求 `<answer>` 的简短提示，用来衡量协议本身让 V0 损失多少）
和失败分类；train 上 4 个样本中答案奖励不全相同的题目比例（GRPO 能从答案得到信号的比例）。

## 8. 运行器改动（回应你在第三次预检中的观察）

## 11. 修订记录

**修订 1（2026-11-09，S3 实施中；在对 validation 与 test 运行 CF-Geo 流水线之前，只依据 train）**：第 3.2 节第 2、3 步改为下面的做法，
第 1、4、5 步和标准答案的规则不变。

- 原来的第 2 步（整个框填成背景色，框外一圈颜色不均匀就排除）在 train 上把 431 个候选排除到只剩 60 个（14%）。
  主要原因有两个：数字紧挨着线条，一圈里有线条的像素（166 个）；数字带单位，例如 “3 cm”“4 in.”（153 个）。
- 新的第 2 步：在框（外扩 2 像素）里，不伸出框外的墨迹连通块就是数字本身，连同它淡的抗锯齿边缘一起改成背景色。
  从框外伸进来的线条保持不动；这样的线条只要有一个像素和数字同色（例如黑白图里的黑线碰到黑色数字），就无法把两者分开，排除这道题。
  数字后面可以跟 cm、mm、m、km、in.、ft、yd、units，单位原样重画。
