## 二、`pilot` 任务

运行方式：`bash colab/launch.sh pilot --session p3`。预计 1.5–2.5 小时（需要 76 步重试时再加 1–1.7 小时），约 10–17 CU。

| 步骤 | 内容 | 预计用时 |
|---|---|---|
| env_report、verify_pack | 与 `v0` 相同 | 约 2 分钟 |
| pytest | VM 上的完整 CPU 测试（隐藏 GPU） | 约 5 分钟 |
| register_check | 登记表与配置一致；这台 VM 上的数据与登记的 SHA256、609 行一致 | 几秒 |
| drive_probe | 必需：Drive 写入、读回、核对、删除 | 约 1 分钟 |
| vllm_env | 建 vLLM 环境（冻结的运行时用 vLLM 生成） | 约 10–15 分钟 |
| pilot_v5 | `rl_v5` 种子 1，正式形状 40 步；第 20、40 步的 checkpoint 和 `final/` 复制到 Drive 并核对 | 约 40–65 分钟 |
| pilot_resume | 小形状：第 1 步后停下，本地目录改名留存，从 Drive 取回 checkpoint-1 到原目录，恢复到第 2 步 | 约 15–20 分钟 |
| pilot_rl_ans、pilot_rl_v4、pilot_rl_v5_placebo、pilot_rl_blind | 各 3 步，正式形状 | 每个约 8–14 分钟 |
| pilot_v5_retry | 只在 `pilot_v5` 的 G4 不通过、而它的 G1、G2、G3、G6 都通过时运行：`rl_v5` 76 步 | 0 或 1–1.7 小时 |
| decide_pilot | 判定 G1–G6，写 `pilot_gates.json`，把结论写成 Drive 上的 `PILOT_LATEST.json`（通过或不通过都写） | 约 1 分钟 |

`decide_pilot` 不依赖前面的步骤是否成功：缺少的试跑按未通过处理。它还用 `train` 将要用的同一段代码读出训练代码的 SHA256 和包版本，
与试跑任务记录的比较；读不出来或不一致时试跑不通过（D63）。

## 三、`train` 任务

运行方式：`bash colab/launch.sh train --session p3`，可加 `--max-hours H`。一次运行跑到这台 VM 的时间用完为止，之后重新准备 VM 再运行同一条命令。

1. **开始前的核对**（任何一项不符就一个任务也不开始，摘要显示原因）：Drive 可用；最新的试跑通过，且登记表 SHA256、冻结运行时、
   训练代码的 SHA256 和包版本都与它相同；Drive 上已有代码基准时，训练代码也与基准相同。
2. **逐个任务决定**（按登记顺序 1–12，可选的 13–14 只在 12 个都完成或失败后考虑）：
   - Drive 上已完成或已失败：跳过；有另一个作业的有效认领：跳过；
   - 没开始过的任务：2026-11-29 00:00 UTC 之后、或推算的余额低于 150 CU 时跳过；已经开始的照常恢复；
   - VM 本地盘剩余不到 15 GB，或 Drive 剩余不到 2 GB：本次运行停止，摘要显示未通过（需要你换 VM 或腾出 Drive 空间）；
   - 预计在截止时间前跑不完：本次运行到此结束，这是正常结束（D62）；
   - 其余：开始，或从 Drive 上最新的已核对 checkpoint 恢复。
3. **一个任务的执行**：写认领并确认；第一个正式任务写代码基准；新任务写 `STARTED.json`；把本地已有的目录改名留存；需要时从 Drive 取回；
   在监督进程下运行 `train_rl --registered`。checkpoint 一写完就在后台复制到 Drive 并核对，核对通过后永久删除 Drive 上更旧的一个
   （不进回收站：回收站里的文件仍占配额，D60）；第 228 步后复制 `final/` 和运行文件，核对通过后写 `COMPLETED.json`。
4. **结束方式**：完成；中断（到截止时间等，下次恢复）；设置问题（作业停止）；计算失败（记到 `failures/`，有时间就立即重启一次，
   第二次写 `FAILED.json`）。

两台 VM（例如 `p3` 和 `p3b`）可以同时运行 `train`：它们用 Drive 上的认领文件分开任务（D61）。

## 四、写这部分代码时发现并改正的问题

都是在实现和本机测试中发现的，没有影响任何已有结果：

1. 计算截止时间时，容器启动时间为 0（测试里构造的值）会被当成“读不到”，改为只在读不到时才回退。
2. dry run 时 VM 的根目录可能还不存在，检查磁盘空间时改为向上找到存在的目录。
3. 训练入口事件里的 checkpoint 路径是相对路径时，改为按训练进程的工作目录解析。
   同一秒内两次把本地目录改名留存（计算失败后立即重启）时新名字会重复，改为重复时加序号。
4. `bootstrap` 在代码变化时会删掉整个 `repo/` 再解包，而登记的输出目录在 `repo/runs/` 下；改为把 `repo/runs` 链接到
   `/content/p3/runs`，checkpoint 不随代码更新被删（D64）。
5. `rclone purge` 在 Google Drive 上默认把目录移进回收站，回收站里的文件 30 天内仍占配额（见 rclone 论坛的
   [这个讨论](https://forum.rclone.org/t/rclone-purge-does-not-decrease-space-used-in-google-drive/22428)），所以按 D58 删除旧 checkpoint
   实际省不下空间；12 个任务被替换的 checkpoint 约 22 GB。改为 `--drive-use-trash=false` 永久删除，并在每个任务开始前检查 Drive
   剩余空间（D60）。
