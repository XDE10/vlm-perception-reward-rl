## 二、凭据的处理方式

- PAT 只由你在 VM 的终端里输入。运行器不读取、不上传、不记录它，请求里只有文件路径 `/content/gh_credentials`。
- VM 上的 git 只用这一个凭据文件（先清空其他 credential helper），并设 `GIT_TERMINAL_PROMPT=0`：凭据不对时直接失败，不会卡在输入提示上。
- 任务开始时先用 `git push --dry-run` 验证写权限，这一步不写入任何东西。
- 推送前把结果里形似凭据的字符串替换成 `REDACTED`。本阶段新增两类：网址里的 `用户:令牌@`，以及细粒度 PAT（`github_pat_...`）。
- 测试里用假凭据，检查它没有出现在推送的任何文件里。VM 上运行的单元测试只用临时路径和本地仓库，不会碰到真实凭据，也不访问 GitHub。
