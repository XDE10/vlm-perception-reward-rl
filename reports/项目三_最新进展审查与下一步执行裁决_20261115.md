## 3. 两条独立实验轨道

### A. Shuffle-R1 单卡复现轨道（附件讨论的主要对象）

目标是尽可能忠实迁移作者的 Shuffle-R1 3B 配置到单张 RTX PRO 6000 Blackwell 96GB。单卡只改变物理执行方式，不能改变算法逻辑批次与训练预算。

作者官方资料核对结果：

- 官方仓库：`xiaomi-research/shuffle-r1`，默认分支 `main`。
- 官方 3B 启动脚本：`examples/qwen2_5_vl_3b.sh`。
- 官方数据：`XenoZLH/MMRL30k`，样本字段为 `problem`、`images`、`answer`、`source`；README 描述约 2.1k Geometry3K + 27k MM-EUREKA 样本。
- 3B backbone：`Qwen/Qwen2.5-VL-3B-Instruct`。
- 官方 3B 脚本明确使用 n=16、top_p=0.99、purning_ratio=0.5、PTS pairwise、KL coef=0、20 episodes，并声明作者训练使用 8×H800-80G。
- 官方通用 `examples/config.yaml` 默认是 7B、n=5、TP=2、8 GPU 和 math12k；不能原样当成 3B 正式配置。
- 作者没有报告单张 RTX PRO 6000 的训练结果，不能预先保证单卡效果与 8×H800 一致。

**目标逻辑批次：**

| 项目 | 作者参考逻辑形状 | 单卡实现目标 |
|---|---:|---:|
| prompts / logical rollout batch | 512 | 512 |
| 每题 rollout | 16 | 16 |
| 候选轨迹 | 8,192 | 8,192 |
| PTS 后保留轨迹 | 4,096 | 4,096 |
| 每轮 optimizer update | 4 | 4 |
| 参考 DP 布局 | 8 | 虚拟重建 8-rank 参考布局 |
| 参考微批 | 4 | 保持参考微批权重，物理微批可为 1 |
| ABS replay | 8 | 8 |

关键原则：所有物理 chunk 必须由同一策略版本生成；收齐完整逻辑批次后统一做 PTS/ABS；保留作者的样本排列、每次 optimizer update 样本组成与 token-loss 权重。不能把物理 chunk 当成独立 RL batch，也不能简单地把 microbatch 改成 1 后普通平均 loss。

B512/G128/n=16/保留率 0.5 的 ABS 每轮需要 256 个 pair。正权重 pair 支持数低于 256 时必须 fail closed，不能 uniform-fill 或静默重采样。

### 阶段 4：同预算 PTS 对照

两组从同一个冻结 checkpoint 和同一份冻结首步候选轨迹开始，逐行 hash 必须一致：

- PTS 组：作者 pairwise PTS。
- Uniform 组：每题相同保留数量的 uniform sampling。
- 比较 PTS 本身时两组都关闭 ABS；完整算法另设 PTS+ABS 组。
- 两组固定有效训练 token、样本数、optimizer update 数、LR 与训练 token budget。
- 同时报 GPU 秒、生成 token、训练 token、有效 pair 数、梯度范数、reward/accuracy、格式失败率。
- 先做冻结 batch 机制对照，再决定是否做多 batch 短程效果比较。

不能只保证 GPU 时间相同而 token 不同，然后称作“同预算”。

### 阶段 5：完整训练是否值得跑

作者设置约 30k 数据、512 prompts/outer step、20 episodes，粗略约 1,180 个逻辑 outer steps（实际按 drop_last 与数据集精确长度重算）。完整训练预算只能由阶段 3 实测单步时间外推：

`预计 CU = (B512 单步秒数 × 预计逻辑步数 + 验证/保存/环境开销) / 3600 × 实测 CU/h`

必须至少保留 20% CU 作为恢复与终评余量。若无法在预算内完成，改为明确标注的短程/单 epoch研究，不得声称复现作者 20-episode 设置。
